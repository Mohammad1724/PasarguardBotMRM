## بکاپ‌گیری

از **پنل مدیریت → بکاپ ربات** بکاپ دستی بگیرید یا فاصلهٔ بکاپ خودکار را تنظیم کنید. مقصد، کانال اختصاصی بکاپ در بخش مدیریت لاگ‌ها است. فایل ZIP شامل `database.sql` و در صورت وجود فایل `.env` است؛ سشن تلگرام، Redis و خود پنل پاسارگارد در این بکاپ نیستند.

فایل می‌تواند توکن، رمز و اطلاعات کاربران را در بر داشته باشد؛ آن را عمومی نکنید.

## ریستور ایمن

ریستور مخرب از داخل رباتِ در حال اجرا غیرفعال شده است. در سرور، پس از به‌روزرسانی هم ربات و هم اسکریپت مدیریت، اجرا کنید:

```bash
sudo pasarguardbot restore /absolute/path/to/backup.zip
```

۱. اسکریپت تأیید صریح می‌گیرد و ربات را متوقف می‌کند.
۲. بکاپ ایمنی از وضعیت فعلی در `logs/restore-safety` ذخیره می‌شود.
۳. ZIP بررسی، SQL وارد و migrationها اجرا می‌شوند.
۴. کلیدها از جدول `secrets` خوانده می‌شوند.
۵. فقط پس از موفقیت کامل، پیشنهاد روشن‌کردن مجدد ربات نمایش داده می‌شود.

تمام نویسنده‌های دیگر همان دیتابیس نیز باید متوقف باشند. MariaDB و Redis باید آماده باشند. ریستور هم‌زمان مجاز نیست.

## کلیدهای بکاپ جدید و قدیمی

در نسخه جدید `CRYPTO_KEY` و `WEBHOOK_SECRET` داخل دیتابیس هستند. نبود این مقادیر در `.env` بکاپ جدید، به‌تنهایی به معنی گم‌شدن کلید نیست.

برای بکاپ قدیمی فاقد جدول secrets، فایل `.env` با کلید اصلی لازم است؛ migration آن را به دیتابیس منتقل می‌کند. کلید تصادفی جایگزین، رمزهای قدیمی پنل را بازیابی نمی‌کند. مشخصات تلگرام و اتصال دیتابیس نصب فعلی تعویض نمی‌شوند.

## شکست ریستور

در صورت خطا **ربات خاموش باقی می‌ماند**. پیش از restart، لاگ را بررسی کنید و از بکاپ معتبر یا بکاپ ایمنی استفاده کنید. بازگردانی خودکار SQL نیمه‌واردشده انجام نمی‌شود.

بکاپ انتخاب‌کنندهٔ نام دیتابیس دیگر، برای جلوگیری از حذف اشتباه داده رد می‌شود؛ ابتدا آن را در محیط جدا با نام دیتابیس متناظر بازیابی کنید. فقط بکاپ معتبر و مورداعتماد خودتان را وارد کنید.
